# visualizing-skill-packages 优化方案

状态：设计已确认，尚未实施。本轮只记录方案和术语，不修改技能指令、解析器、校验器、渲染器或分发产物。

## 目标

把 skill 优化为 Agent 驱动、来源可追溯的语义流程解释工具。质量以语义保留、关系有据和实际可读为准，不以标题相似度、节点数量或流程看起来完整为准。

领域术语以 [GLOSSARY.md](../GLOSSARY.md) 为准；本文记录取舍、实施顺序和验收条件，不重复定义术语。

## 已确认的决定

| 决定 | 采用方案 | 原因与取舍 |
|---|---|---|
| 语义分类 | 原文事实、建模归纳、工程建议分开 | 保留解释能力，同时避免把新增流程关系当成原文要求 |
| 正式交付入口 | Agent 阅读原文、提取并审计语义图，再调用固定渲染器 | 复用现有 Agent 的理解能力；网页 Markdown 上传仍是保守预览，不承诺同等语义质量 |
| 主图抽象单位 | 语义阶段优先，编号作为来源锚点 | 允许有依据的合并和拆分，但必须保留原有条件、先后、可选性与适用范围，并记录映射 |
| 工程建议触发条件 | 用户明确要求改进流程时才生成，在事实流程之外单列 | 解释原文不自动扩张为重新设计原流程 |
| 本轮执行范围 | 只完成方案文档 | 实际技能和代码变更另行进入实施与验证 |

## 优化范围

后续变更同时覆盖技能指令与其配套实现，不以继续增加禁止语句替代修复。

- 技能流程与参考材料：收敛提取、审计、渲染、交付各步及其完成条件。
- 图契约与校验：让语义分类、证据和建模理由在导入、导出、显示中保持一致。
- Markdown 预览：保留完整原文、步骤正文及资源引用，明确预览能力范围。
- 通用渲染：解决标签碰撞、追踪视觉状态和建模归纳的可识别性。
- 分发：实现验证完成后，同步源码构建产物与本地安装的技能包。

现有其他输出路径保留；本轮不扩展新格式、不另建网页语义服务、不引入新的模型调用后端。

## 语义与交付契约

### 来源与覆盖

- 从原始输入保存源快照及其 SHA-256；来源页显示该快照，不以解析后的 JSON 代替原文。
- 每个主图阶段能映射回原文；每次合并或拆分记录涉及的原文范围及理由。
- 必要动作、条件、约束和资源都有明确去向。主图摘要允许简短，详情和证据保留理解原意所需的正文。
- 示例和代码块可不进入主流程，但仍保留在源快照中；覆盖记录说明它们为何被排除。
- 引用出现某个主题，不等于引用支持围绕该主题新增的任意流程关系。节点和边分别审计。

### 分类与关系

- 图契约明确区分原文事实与建模归纳，替代当前含混的 `inferred` 用法；沿用可复用的证据与理由信息，不增加第二套并行判定规则。
- 建模归纳说明合并、拆分或关系表达如何保持原意；它不改变条件强度、时序、可选性或迭代范围。
- 工程建议单列在图外说明中，解释改进目的与新增假设，不作为事实流程边，也不参与事实流程追踪。
- 原文没有规定失败目标时，保留该缺口。原文只要求检查时，先表达检查动作；只有原文支持路由条件时才表达相应分支。
- 约束与资源关联继续和执行关系区分；资源引用不等于资源已存在、已执行或已通过验证。

### 两类缺口分别处理

| 情形 | 处理 |
|---|---|
| 原文本身没有说明失败目标、退出条件或存在冲突 | 保留原文与说明，作为来源缺口交付，不制造确定关系 |
| 原文已有必要步骤、条件或资源，但提取结果遗漏或曲解 | 判为提取未完成，修正后再交付，不能用警告代替修复 |

### 固定渲染器

- 一个输入的提取结果通过数据表达；修复提取问题时修改图数据，不单独修改该输入的生成 HTML、样式或坐标。
- 通用渲染缺陷在源码中集中修复，并用多个输入验证后更新统一模板。
- 渲染器负责呈现已审计的图，不在渲染时补出语义分支、门禁、回退或成功终点。

## 实施顺序与完成条件

### 1. 统一图契约和技能语义规则

工作：

- 将已确认的分类和归纳规则落实到 [技能指令](../skill/SKILL.md) 与 [图校验器](../skill/scripts/validate-graph.mjs)。
- 放开“一项编号主步骤只能对应一个节点”的机械限制，要求来源映射代替标题一一对应。
- 保留必要的硬约束，将普通归纳与新增工程建议分开；使样例、导入导出和展示遵循同一规则。
- 迁移现有 `inferred` 使用处时逐项核对其含义，不能只批量重命名或将全部旧数据默认为原文事实；不保留旧语义别名。

完成条件：

- 相同分类在文档、图数据、校验和展示中含义一致。
- 样例中的未知失败目标不再混入事实流程。
- 明确检查结构合法性与检查语义正确性的区别；非空 evidence 不能被当成语义正确的证明。

### 2. 修复内容保留，建立可核对的覆盖记录

工作：

- 在 [parseSkill](../src/graph.js) 中把明确步骤的正文、嵌套清单、条件和资源归入所属步骤，而不是遇到 Step 标题后跳过正文。
- 保留完整源文，使文件导入和 Markdown 渲染都能查看原始 Markdown。
- 保守预览不把普通无序清单自动解释为互斥操作；无法确定执行语义时明确说明，不冒充 Agent 语义提取。
- Agent 完成提取后，另做一次逐项覆盖与逐边核对，记录合并、拆分、排除示例和来源缺口。
- 在 [现有解析测试](../tests/graph.test.mjs) 中保留能捕获正文丢失、资源归属错误和无依据关系的行为回归；不只断言子清单没有变成额外节点。

完成条件：

- 备份流程的权限要求、步骤正文、脚本和政策引用均可找到，且归属于正确阶段。
- 合并和拆分后的主图仍覆盖所有必要内容，没有因抽象而丢掉限定条件。
- 原文页显示完整输入；主图详情不是标题的重复。
- 覆盖记录能将遗漏与有理由的归纳区分开。

### 3. 修复通用渲染和追踪呈现

工作：

- 在 [视图与走线](../src/main.jsx) 中使用曲线真实标签位置，并依据实际节点和标签边界处理碰撞，覆盖普通边、回流边和自回环。
- 统一节点、SVG 线条、箭头和独立标签的追踪状态；约束与资源关联采用一致、明确的上下文呈现，不伪装为执行链。
- 保留 [方向敏感、环路安全的追踪计算](../src/trace.js)，修复展示联动而不是重写已正确的遍历。
- 在 [样式](../src/style.css) 和图例中使建模归纳可识别，同时保留点击查看理由与证据的能力。

完成条件：

- 默认样例中 “Already understood: skip” 不再覆盖 understand 节点，“Functionality clear” 不再与 “Constrains content” 重叠。
- 选中或悬停时，节点、线条和标签的明暗状态一致；关闭详情或点击空白后恢复。
- 真实浏览器中验证长标题、长标签、分支、回路及资源关联；完整缩略截图不作为文字可读性的唯一证明。

### 4. 精简技能文档并验证分发

工作：

- `SKILL.md` 保留模式选择、执行步骤、完成条件及必要硬约束；详细审查规则和正反例放在按需读取的参考文件中。
- 在改写技能前，用当前技能运行有针对性的行为场景，记录旧行为；改写后复跑同类场景，验证行为变化，而非只比较措辞。
- 先通过 [渲染命令](../skill/scripts/render.mjs) 生成实际 HTML，再在指定 CDP Chrome 中验收。
- 源码修复与浏览器验证完成后，统一构建、更新包内模板并同步本地安装技能；不单独修补某个生成文件。

完成条件：

- 规则有唯一维护位置，参考材料有明确读取触发条件，各执行步骤有可核对的结束条件。
- 未调用所描述的业务脚本或产生实际输出时，交付物不声称执行、生成或验证成功。
- 源码、包内模板和安装版本一致；新输入复用同一套已验证渲染器。

## 跨主题验收场景

| 场景 | 必须验证的消费者可见行为 |
|---|---|
| 带 Step 标题的备份流程 | 权限限定、正文和资源完整保留；无其他技能的阶段残留 |
| 编号步骤与语义阶段不一一对应 | 有依据的合并、拆分保持原有关系；覆盖记录能回到原文 |
| 插件技能开发 | 区分检查动作、来源缺口和工程建议；不将“No Packaging Needed”变成打包动作 |
| 调试流程 | 保留假设验证、重试范围和人工架构复核，不把暂停讨论画成成功结束 |
| PDF 替代操作 | 每个操作关联自己的脚本；示例代码不变成执行步骤；不靠所有 Quick Start 清单都是替代操作的假设 |
| 长标签、分支、回流、自回环和关联线 | 标签不互相覆盖或遮挡节点；方向正确；追踪状态一致；理由与证据可查看 |

程序校验负责结构、引用完整性及可机械核对的来源一致性；Agent 对条件含义、时序、可选性和归纳是否保真负责。结构校验通过不替代语义审查。

## 每次正式交付的材料

- 原始源快照及 SHA-256。
- 已审计的语义图 JSON。
- 覆盖记录：原文范围、对应节点或边、处理方式，以及归纳、排除或缺口的理由。
- 使用统一模板生成并实际打开验证的 HTML。
- 仅在用户明确要求流程改进时，另附图外工程建议。
