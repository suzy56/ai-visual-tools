# 02: 解释结果明确区分原文事实与建模归纳

**What to build:** 使用者从输入图数据、校验、生成 HTML 到查看图例、详情和导出，都能一致地区分原文事实与建模归纳，并检查证据和归纳理由。含混的既有推导标记在同一票内贯穿生产者与消费者完成迁移，不另起平台重构或保留新旧两套语义。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 图数据统一表达原文事实与建模归纳；校验、导入、导出、图例和详情对类别的解释一致。
- [ ] 节点和边都具有可核对的原文证据；建模归纳另有说明如何保持原意的理由。引用与主题相关不等于证明任意流程关系。
- [ ] 工程建议不能借用建模归纳类别进入事实流程；原文没有规定的失败去向不作为事实边保留。
- [ ] 既有含混推导元数据逐项根据真实来源迁移，不批量重命名后默认判为原文事实；全部受影响调用方、样例、文档和通用模板采用同一契约，不保留旧语义别名。
- [ ] 无效类别、缺失必要来源信息和缺少归纳理由的输入被明确拒绝；保留既有重复标识、悬空关系和非法字段的失败行为。
- [ ] 图例与节点、连线的可见标识足以区分类别；点击节点、边和边标签可以看到对应证据及归纳理由，导出再导入后仍保持这些信息。
- [ ] 使用一组原文事实与保持原义的归纳案例完成正反验证；程序结构校验通过不被表述为已证明语义正确。
