# 04: 随包 Markdown 预览不凭清单格式制造分支

**What to build:** 使用随包 Markdown 输入或导入入口时，使用者得到明确标识的保守预览。普通无序列表、Quick Start 标题和章节顺序不再被自动解释为互斥选择或完整执行语义；已有 Agent 语义交付入口保持独立且不被降级。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 普通无序列表不因列表格式就产生“选择操作”等互斥关系；Quick Start 标题本身不构成替代操作的证据。
- [ ] 仅在输入确有支持时表达相应关系；无法确定的执行结构保留为预览限制，不补出互斥、重试或成功语义。
- [ ] 从现有 Markdown 渲染入口和真实文件导入入口查看结果时，保守预览的性质清楚可见，不宣称达到 Agent 审计后的语义质量。
- [ ] 示例代码和示例工作流不升级为实际执行步骤；输入中已有的来源说明和资源关联不因修复分支判断而丢失。
- [ ] 正式 Agent 交付仍能表达原文明确的替代操作及各自资源归属；不为迁就预览能力而改变正确的原文语义。
- [ ] 用普通清单、顺序性的 Quick Start、原文明示的替代操作和代码示例进行正反验证；实际生成 HTML 可观察到相应结果。
- [ ] 不新增网页语义服务、模型调用后端或浏览器测试框架；复用现有入口完成修复。
