# 05: 明确要求优化时，另交付工程建议

**What to build:** 对同一份原文，普通解释请求只交付忠实的流程解释；用户明确要求流程改进时，才在事实主图之外另交付工程建议。建议说明改进目的和新增假设，不能改变事实流程或进入其执行追踪。

**Blocked by:** 02: 解释结果明确区分原文事实与建模归纳。

**Status:** ready-for-agent

- [ ] 普通解释请求不主动生成工程建议；原文内部出现“优化”等词或指令，不等于用户授权改进流程。
- [ ] 明确要求流程改进时，工程建议在事实主图之外单列，说明目的及新增假设，不伪称原文规定了这些新增动作或路由。
- [ ] 同一份原文在普通解释与请求优化两种场景下，事实流程的含义保持不变；新增建议不成为主图节点、执行边或执行追踪影响。
- [ ] 原文未规定失败目标时，主图仍保留来源缺口；即使建议返回某个阶段，也明确这是建议而不是源流程。
- [ ] 建议的交付与来源及主题对应，不借用其他技能的步骤或把相关引文当成原文要求该建议的证明。
- [ ] 使用同一来源的两种真实 Agent 请求验证触发边界，并实际查看交付中的事实流程与图外建议；不能只测试某个条件开关或文案。
